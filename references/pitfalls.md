# 可迁移的踩坑清单

从一个真实完成的项目里 88 条沉淀经验中挑出的 **20 条**，标准是：**换一块板、换一个题目仍然成立**。

按阶段归类。每条给：**触发条件 → 现象 → 正确做法**。

---

## 一、资源判读类

### 1. 不能用综合数判断"布不布得下"

- **触发**：综合报告说 LUT 只用了 30%，你觉得还有空间
- **现象**：实现阶段超容，`[DRC UTLZ-1]` 直接中止布线
- **正确做法**：只看 `impl_1/*_utilization_placed.rpt`。综合报告把 OOC IP 当黑盒，总数比实际小 20% 以上

### 2. `ram_style="block"` 是愿望，不是结论

- **触发**：写了 `(* ram_style = "block" *)` 就以为进了块 RAM
- **现象**：资源暴涨，一个 32Kb 存储吃掉 86% LUT
- **正确做法**：按**实例名 + 原语类型**查。判据是看到 `RAMB36E1`/`RAMB18E1`，看到 `FDRE` 就是失败了
- **根因**：读口带异步复位 → 综合器放弃块 RAM 推断 → 全部铺成触发器
- **修法**：读口去异步复位、读写口拆成两个 `always` 块、地址截位

### 3. 同一个坑会以另一种形式再踩一次

- **触发**：修好一处推断失败，以为问题解决了
- **现象**：另一个模块（例：谱平均累加器）以同样的原因退化，LUT 从 35% 推到 53%
- **正确做法**：修完一处，**全库搜同类写法**（`always @(posedge clk or negedge rst_n)` 里读写同一个存储）

### 4. 改完必须确认"我改的那一个东西真的变了"

- **触发**：改了一行，重跑报告，总数看起来差不多
- **现象**：那个改动**从未生效**，被总数掩盖 25 天
- **正确做法**：改前记下**该实例**的资源，改后再查**同一个实例**。不看总数

### 5. 调试核开关会改变全部数字

- **触发**：报告里的资源/时序和你上次看到的不一样
- **现象**：ILA 类调试核占 3.5% LUT + 大量布线，开着和关着是两套数
- **正确做法**：报告里**必须写明**调试核是否关闭；交接版本一律关闭，并留下"要调试就改回 1'b1"的注释

## 二、验证方法类

### 6. 只能对上"正确结果"的模型，抓不到真实现象

- **触发**：写了 Python 模型，和 RTL 在理想信号上一致
- **现象**：真实信号下出现"看起来很合理的错值"，模型复现不了 → 无法定位
- **正确做法**：模型要能**复现板上的错误读数**。能复现错误，说明抓到了真实行为

### 7. 测量类读数必须覆盖极端值

- **触发**：所有测试都在 1kHz 附近做
- **现象**：最大 bin / 最大 fs / 最大系数处的位宽溢出 bug 躲了很久
- **正确做法**：每个测量项至少测三个点：**最小 / 典型 / 最大**

### 8. "读数看起来正常"是危险信号，不是好信号

- **触发**：信号已经衰减到噪声本底以下
- **现象**：峰峰值读数**停在本底附近不再下降**，而不是继续变小
- **根因**：峰峰值统计的是"最大值减最小值"，噪声起伏被当成信号记入
- **正确做法**：读数出现"不再变化"的平台区时，先怀疑已失效。需要一条独立量程互相印证

### 9. 静默命令只能靠可观察量判断

- **触发**：发了不回 ACK 的命令（触发类、扫描类）
- **现象**：发得出去，但不知道生没生效
- **正确做法**：每条静默命令**必须有**一个可观察副作用（某个读数变化、某个状态位翻转）。文档里逐个列出

### 10. 删功能时"直接报错"优于"静默忽略"

- **触发**：废弃一条命令，但保留帧格式兼容
- **现象**：发出去不生效，最难查
- **正确做法**：要么回一个明确的错误码，要么在文档里显著标注"已废弃，无效果"

### 11. 界面类功能必须端到端验证

- **触发**：脚本能读到数据，就认为功能好了
- **现象**：界面从来没显示过（校验和口径错 → 每帧静默丢弃）
- **正确做法**：**从界面看一次**。脚本能读 ≠ 界面能用

## 三、协议与接口类

### 12. 多帧类型共存时，校验和口径必须统一

- **触发**：新增一种上行帧，复制了别处的组帧代码
- **现象**：一种帧从帧头起算校验和，另一种从类型字起算 → 接收方永远判失败
- **正确做法**：把"校验和起算位置"写进协议文档的**显式条款**，并让审计脚本同时覆盖上行帧

### 13. 校验和恒差 1 的经典来源：把帧头算进去了

- **触发**：帧头是 `5A A5`，和为 `0xFF`
- **现象**：结果永远比预期小 1（`0xFF ≡ −1`）
- **正确做法**：起算位置从**类型字**开始，不从帧头

### 14. 命令号必须有唯一分配表

- **触发**：口头约定"这个号给我"
- **现象**：同一个号出现在三份文档、三种用途
- **正确做法**：分配表是唯一事实源。定新命令前先占位，占位后立刻在速查表加一行

### 15. 端口漏接，综合器不会报警

- **触发**：模块实例化时少连两个 input
- **现象**：Verilog 把未连接输入当无驱动网络，综合器零警告，功能从来没跑过
- **正确做法**：每个模块**至少一个**不依赖 UI 的可观察量，逐条验证

## 四、环境与工具类

### 16. 别把"只过了语法检查"说成"仿真通过"

- **触发**：环境只能跑 `xvlog`/`xelab`，跑不了 `xsim` 执行
- **现象**：把 elaborate 通过当成功能验证通过
- **正确做法**：明确区分 `elaborate 通过` / `仿真通过` / `上板通过`。文档里的措辞必须对应实际做到的层级

### 17. 批处理文件一律纯 ASCII + CRLF

- **触发**：`.bat` 里写了中文
- **现象**：cmd 按本地代码页读批处理，中文在 `(...)` 或 `set` 里被误解码，行为不可预期
- **正确做法**：`.bat` 纯 ASCII + CRLF；中文说明放到 `.md` 里

### 18. GUI 崩溃是常态，关键操作要有批处理通道

- **触发**：只靠 GUI 完成综合/烧板
- **现象**：GUI 崩了就卡住
- **正确做法**：重建、烧板、固化各有 `.bat`，走批次模式。强杀 GUI 后确认后台服务进程（`hw_server`、`cs_server`）没有残留

### 19. 路径硬编码会在"目录被搬家"时静默失败

- **触发**：脚本里写死桌面绝对路径
- **现象**：把目录改名/搬家后，脚本报"失败"但不报**原因**（异常被 `except` 吞掉）
- **正确做法**：路径**自动探测**（候选列表 + 扫父目录）；`except` 里必须打印异常类型和消息

### 20. 代码重复生成资产，会让"包"和"仓库"不断错位

- **触发**：文档/PDF/压缩包由脚本生成
- **现象**：改一次代码 → 重新生成 → 包过期；再提交生成脚本 → 又过期
- **正确做法**：**提交所有代码 → 生成 → 打包 → 之后不再动代码**。并且每次打包后**逐文件 md5 比对**，而不是看时间戳

## 附：三条元规则

从这 20 条里再抽一层，是三条能覆盖其余所有的：

**① 凡是"看起来正常"，都要有一个独立量去证伪。**
> 读数停在本底不动、功能有按钮没反应、包看起来是最新的 —— 都属于这一类。

**② 凡是"我改好了"，都要确认"那一个东西真的变了"。**
> 不看总数、不看整体、不看时间戳。看那个具体实例/那个具体文件/那一行。

**③ 凡是"失败"，都要能说出原因，不能只说结果。**
> 静默丢弃的帧、被吞掉的异常、没连的端口 —— 它们的共同点都是"只告诉你结果，不告诉你原因"。
